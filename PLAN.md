## 1. Архитектура
```
API региона 39 ──fetch.py──┐
локальный JSON ────────────┴─> normalize.py ─> rules.py ──┐
                                                          ├─> report.py (дедуп по ID, атомарная запись) ─> reports/*.json
                                           ai.py (LLM) ───┘
```
- **Правила** (rules.py) — надёжный каркас: пропуски, противоречия числа/графика/занятости, типовые «размытые» формулировки.
- **ИИ** (ai.py) — то, что правилами не поймать: неоднозначности в свободном тексте обязанностей и требований, нетипичные формулировки. Шаг ИИ влияет на отчёт напрямую.
- **Защита от галлюцинаций:** цитата ИИ обязана дословно встречаться в исходном поле, иначе замечание отбрасывается. Это прямо отвечает требованию «без вымышленных фактов».
- **Отказоустойчивость:** если LLM недоступна, отчёт всё равно строится по правилам, число сбоев — в `ai_errors`.
- Стек: Python 3.11, только стандартная библиотека (ноль зависимостей — жюри запускает в одну команду).

## 2. Этапы и сроки (ориентир; подставьте дату дедлайна)
**Этап 1 — каркас (✅ сделан в этой сессии).** Структура, правила, CLI, тесты, workflow, учебный отчёт.

**Этап 2 — живой API (✅ выполнен 2026-11-24).**
Живой API региона 39 оказался доступен. Подтверждено:
- `offset` — номер страницы, страницы не пересекаются; в регионе ~4232 вакансии.
- Схема совпадает с учебным примером (`job-name`, `duty`, `requirement`, `salary_min/max`, `schedule`, `employment`, `addresses.address[].location`, `vac_url`); дополнительно используется поле `shift` (уточнение смены) — добавлено в анализ.
- Прогон 200 вакансий: 105 с замечаниями, 130 замечаний (employment 68, schedule 35, duties 27). Ложные срабатывания workplace устранены (правило срабатывает только когда адрес неполный).
- Портал нестабилен (HTTP 500 на середине пагинации) → в `fetch.py` добавлены ретраи.
- Оставшийся пункт: запускать `run` при недоступном API у себя и убедиться, что старый отчёт не перезаписан (проверено эмуляцией отказа, код 2).

**Этап 3 — ИИ (🔜, ~2–3 ч).**
1. Поставить Ollama, `ollama pull qwen2.5:3b` (или модель крупнее, если хватает железа).
2. `python main.py check --input data/sample_api_response.json --ai`; смотреть `ai_errors` и долю отброшенных цитат.
3. Подобрать промпт (few-shot из 3–4 примеров), убедиться, что рекомендации конкретные и без выдуманных фактов.
4. Запасной вариант без установки: бесплатный тариф OpenAI-совместимого провайдера (Groq/OpenRouter/Gemini) через `.env` — ключ не в репозитории.
5. Оценка качества: 15–20 вакансий вручную разметить («эталон»), посчитать precision/recall по темам.

**Этап 4 — качество правил (~2 ч).** Прогон на 100–200 реальных вакансиях → список ложных срабатываний → правка регулярок и добавление тестов (как с «Охрана объекта»). Жюри использует скрытый набор, поэтому важна обобщаемость, а не подгонка под учебный пример.

**Этап 5 — упаковка (👤, ~1,5 ч).**
1. README: зависимости, команды, формат отчёта, модель/провайдер, шаг ИИ, вклад участников.
2. Публичный репозиторий, закоммитить `reports/sample_report.json` на учебных данных (когда организаторы выдадут учебный пример — заменить), записать SHA.
3. Видео ≤ 3 мин: (а) запуск `run` и получение данных, (б) где вызывается ИИ, (в) открыть отчёт и показать замечание с цитатой и рекомендацией. Ссылка с доступом «для всех по ссылке».

**Этап 6 — по желанию (⏳).** Доп. сценарий «черновик резюме под вакансию» на вымышленном резюме; правило «не выдумывать опыт» — проверять, что все навыки ответа есть в исходном резюме. Простой HTML-просмотр отчёта.
